## Compatibility and limits

- Invalid UUID filters now fail explicitly with HTTP 400 rather than matching empty relationships. Validation is at the existing PostgreSQL UUID-column boundary. Non-UUID/custom-ID paths, mixed polymorphic relation columns and unrelated query operators retain their existing handling. This is not a general MongoDB UUID validation change.
- The existing underscore-delimited CSV format is inherently ambiguous when both a field named foo_bar and a nested foo.bar exist. This fix chooses the longest actual schema name at each level and does not invent a new encoding. Avoid exporting colliding paths together; no lossless round-trip claim is made for such collisions. Unknown legacy paths retain the existing fallback parsing. String-only shared block references retain fallback handling; this batch does not redesign their CSV schema representation.
- CSV import access, per-row validation, batching and user identity remain in the normal pipeline. The persisted integration uses a real stored user and CSV bytes; it does not simulate a browser file picker. The separate streamed CSV first-batch header truncation report #19140 is not fixed or counted.
- PostgreSQL count optimization is deliberately conservative. Unknown cardinality, to-many joins, right joins, localized joins without a proven cardinality and explicit-column counts with joins retain the grouped path. Existing no-join distinct-column handling is preserved. No multi-million-row performance benchmark or live PostgreSQL result was produced locally; emitted SQL and the controlled driver boundary establish the query shape.
- The cron changes affect examples only. The five-minute example uses a range because croner 10 rejects numeric-prefix stepping, and a literal wildcard-step token would terminate a TypeScript block comment. No scheduler default, cadence or dependency changed.
- The Lexical export adds a supported public import for the existing client command singleton. It does not modify the upload drawer, focus handling or server entry. Production client bundling and browser invocation remain remote/manual checks.
- Required rich text still accepts uploads/blocks/decorators without text. Empty headings, linebreak-only paragraphs and whitespace-only text keep their existing treatment; #19227 and related reports are not counted. Optional empty fields remain valid. Existing required translations and node validators are retained.
- No dependencies, lockfiles, CI workflows, quality thresholds, required checks or default access-control policies changed. Existing full PR CI discovers the new specs; all required remote checks must pass on the final commit before merge.
