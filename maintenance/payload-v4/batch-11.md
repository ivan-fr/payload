## Reproduction

The initial three unit files produced **11 failures and three passing controls** on the original sources. The original integration fixture produced **four failures and one passing control**: empty timezone storage, invalid block acceptance, unknown select option acceptance and a search conflict reported as success all reproduced. The valid block partial-update control passed.

The first corrected integration run caught two test setup issues: serializing a JavaScript null directly as a URL query value produces an empty string, and the standard SQLite fixture disables transactions. Null semantics are covered through Local API equality and REST existence queries; the literal string `null` is rejected unless it is an actual configured option. The batch fixture explicitly enables SQLite transactions so the search failure test checks atomic parent rollback rather than assuming it. Other database adapters retain their normal fixture configuration. The valid timezone control uses Europe/Berlin, which is in the generated supported timezone union. Empty-string test inputs deliberately bypass the generated enum type to reproduce malformed runtime requests.

## Compatibility and limits

- Migration tests execute the real runner and migration-order lookup but mock database, transaction and local-file boundaries. No production migrations were run, and no claim of live PostgreSQL DDL execution is made.
- Timezone normalization changes only the generated timezone sibling's empty string. Explicit null/undefined and valid values remain intact; defaults, required validation and the existing override extension remain available. This does not change arbitrary select fields' stored values.
- Missing/unknown blocks now intentionally return 400 instead of silently losing supplied data. Existing row-ID updates can inherit the discriminator; inline and explicitly listed shared block references remain supported. A registered shared block is not automatically allowed in every blocks field.
- Invalid select equality/membership query values now intentionally return 400 across adapters. Labels are not option values. Nullable queries, empty lists, existence and supported string-pattern queries remain compatible. This protects the common query validation boundary; local persistence checks use SQLite rather than live PostgreSQL enum rejection.
- Search synchronization logs an I/O failure once and rethrows the original error for normal parent hooks and shared transactions. Explicit standalone reindex callbacks retain their error-counting behavior when there is no shared transaction; they cannot suppress a shared-transaction failure. The transaction is captured before the write, so a nested rollback cannot hide it by clearing req.transactionID. Transactional reindexing returns 500 and retains its previous index instead of advertising success after rollback. Failed recursion markers are removed so retrying the same request does not falsely skip synchronization. Existing successful duplicate/trash/draft handling and skipSync/default-priority behavior are retained. Atomic rollback requires transactions to be enabled by the adapter; this patch does not enable them globally.
- No dependencies, lockfile, CI workflow, thresholds or default access-control policies were changed. Existing full PR CI discovers the new unit and integration files. Live MongoDB/PostgreSQL and full production UI verification remain remote/manual checks.
