## CSV behavior and tradeoffs

The existing batch processor performs the authenticated, access-controlled reads and transformations once. Each batch is written to a private temporary CSV file using csv-stringify's own casting. Replay parses one batch at a time and writes it against the final column list. This preserves Buffer, Date, bigint, boolean, object and multiline/quoted cell formatting without rereading documents or rerunning hooks.

Memory holds a batch and the column list. CSV output begins after column discovery, so large downloads have more latency before the first body bytes and require writable temporary storage proportional to the prepared export. The temporary directory is removed on completion, errors and cancellation; cancellation stops between batches after any in-flight operation completes. The regression cancels the actual Node-to-Web stream bridge used by download responses and verifies cleanup. JSON and saved-export paths retain their existing behavior.
