## Validation and limits

The new field/join fixture initially failed all three read-access scenarios against the starting implementation. The initial URL/numeric-search tests had nine failures, and the Stripe boundary scenarios rejected oversized metadata or an intent without the old snapshot. Fixture initialization errors were corrected separately and are not counted as reproduced product failures.

Validation commands:

- `pnpm exec vitest run --project unit --testTimeout 30000` — **4,666 passed / 4 skipped**, 519 passing files.
- `PAYLOAD_DATABASE=sqlite pnpm exec vitest run --project int test/server-regressions-batch30/int.spec.ts` — **4 passed**, including actual transaction address persistence and joined reads with public/private documents.
- Package `tsc --noEmit` checks for `payload`, `ui`, `plugin-ecommerce` and `db-mongodb` — passed.
- `PAYLOAD_DATABASE=sqlite pnpm payload server-regressions-batch30 generate:types` — fixture types generated successfully.
- Targeted Oxlint/Oxfmt and staged `git diff --check`. The isolated official SonarJS cognitive-complexity rule checks the affected query/settlement helpers at threshold 15; it is not a SonarCloud quality gate.

SQLite records use the shared fixture lifecycle. Unit tests execute actual query builders and the Stripe SDK while stubbing network/database boundaries where described. MongoDB's native aggregation path already preserved the synthetic branch predicate; the compilation test protects that behavior. The fallback previously discarded branch predicates, so it now resolves their constant collection values before querying, rather than relying on an unsafe collection-list shortcut. No live MongoDB/Postgres database, live payment provider, full application build, rendered relationship drawer or complete browser navigation workflow is claimed verified by this batch. Normal SQL schema migration is required for the added transaction shipping-address columns; no application database was migrated here.

Newly issued intents carry a cart digest; a mismatched or malformed digest is rejected. Legacy intents without a digest retain snapshot comparison when the snapshot exists. The intermediate format with neither digest nor snapshot remains compatible, using persisted transaction items and the other settlement checks. This fallback cannot retrospectively supply a cart digest that an older release never recorded.
