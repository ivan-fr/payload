## Before/after evidence

With original source files restored temporarily, the five focused unit files produced **nine failures and four passing controls**. The completed four-test SQLite fixture produced **four failures**: incomplete variant validation, stale titles, duplicate transaction row IDs and discarded guest email for API-key principals. Fixed bytes were restored in a finally block.

The initial schema test needed versions:false when timestamps:false; after correcting that setup, the original implementation failed specifically on the missing required field promotion. The first corrected variant integration test still allowed a duplicate: it exposed a second ten-row cap in versioned SQL join path handling. Mapping join keys into version.* at the queryDrafts boundary fixed both query construction and result slicing. No workaround changes the default join limit globally.

## Compatibility and limits

- Search configuration validation intentionally fails early for unknown roots in explicit admin.listSearchableFields. It preserves ID aliases and valid relationship/JSON/nested roots; it does not attempt to resolve every dynamic suffix or change request-time query/access validation. No full production Admin navigation is claimed.
- Explicit jsonSchema required:true is opt-in. Required:false still opts out; untouched conditional fields remain optional, and defaulted input properties remain omittable. This changes generated schema presence, not runtime validation, GraphQL nullability or conditional visibility.
- req.user remains intact for authorization, cart access and custom payment methods. A principal from another auth collection follows guest purchaser rules, including email and settlement checks; its ID cannot become a customer relationship simply by matching an ID in another collection. Custom customersSlug values remain supported.
- Cart row IDs and transaction row IDs identify different database rows. Metadata and settlement comparison ignore that database-owned item ID while still checking product, variant, quantity and custom data. The numeric/string normalization is limited to the cart-ID metadata boundary. Existing amount, currency, customer, status and semantic item checks remain in force.
- Stripe tests use the actual SDK with fetch intercepted; no external Stripe call or payment was made. Persisted carts/transactions are real SQLite records; the finalizer is mocked in the new adapter integration test. Existing core finalization/ownership unit suites also pass. The unrelated large-cart Stripe metadata size limit is not fixed or counted here.
- Dedicated variant reads use limit:0 for correctness; versioned reads map public join paths into the internal version namespace. Missing joins and joins:false keep their existing behavior. Live PostgreSQL/MongoDB and very large catalog performance remain remote/manual checks.
- Product-title propagation runs normal variant updates sequentially in the same request/transaction and does not swallow failed writes. Existing child drafts stay drafts. A draft product save refreshes labels in variant drafts, leaving published snapshots untouched; it does not automatically publish child drafts when the product is later published. Option-label-only changes are outside this product-title trigger. User collection overrides retain their normal control of hooks/fields.
- No dependency, lockfile, workflow, quality threshold or default access-control policy changes are included. All new unit/integration specs are discovered by the existing full PR CI.

## UI/accessibility assessment

Scope: server-provided variant choices/titles, generated read-only field metadata and early configuration errors, compared with the starting revision. Assessed WCAG 2.2 A/AA criteria: 1.3.1 (relationships), 2.1.1 (reaching all choices), 2.4.6 (descriptive labels), 3.3.1 (clear invalid configuration/duplicate errors), 4.1.2 (choice values/read-only state) and 4.1.3 (error/update announcements). Automated evidence verifies component-provided options/combinations, actual duplicate rejection, correct persisted titles and readOnly metadata. It does not prove rendered accessible names, reaching the twelfth option by keyboard, screen-reader announcements or the rendered read-only state. No component controls, CSS, focus logic, ARIA or contrast settings were changed. Browser/assistive-technology and visual verification remain pending; no UI demo or accessibility conformance is claimed.
