## Compatibility and verification boundaries

The original scheduler deliberately writes internal job records with privileged queue/delete operations. Changing queue overrideAccess to false broke the existing legitimate secondary-auth scheduling control because the default queue access hook is restricted to the primary admin collection. The final change retains the existing internal job behavior, forwards the acting request and adds the missing target checks before it. It does not claim to redesign independent jobs.access.queue or payload-jobs access policies. Publication-time worker checks remain in place.

The initial-state effect still applies changed nonempty states and does not clear live fields merely because initialState becomes undefined. Replayed effects with the same state no longer erase local edits. The new browser test checks the real reducer and context instead of the effect-boundary harness.

Affected UI journeys and relevant WCAG 2.2 A/AA criteria: form edits surviving drawer/activity transitions (2.1.1, 2.4.3, 3.3.7, 4.1.2); required-field validation and feedback (1.3.1, 3.3.1, 3.3.2, 3.3.3); scheduling error/success announcements (4.1.3); and preventing bulk mutations from affecting records outside the presented selection (3.3.4). Automated evidence supports the request/state/validation boundaries described above. Actual keyboard/focus continuity, error association, toast announcements and assistive-technology behavior remain unverified locally.
