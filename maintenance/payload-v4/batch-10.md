## Before/after evidence

The initial unit reproduction produced 13 failures and eight passing controls across four files. These demonstrate unbounded ID traversal/stack overflow, missing zero-valued ancestors, the SQL-unsafe parent filter, paragraph-wrapped tables, numeric/raw internal link failures and three Ethereal account creations instead of one. A later positive-ID subtree control extends the coverage.

With the original implementations restored temporarily, the four selected persisted integration scenarios failed: descendants were returned as candidate parents, no configured email was sent after numeric-link serialization failed, the generated table was paragraph-wrapped, and manual-global SEO generation returned 403. Fixed source bytes were restored in a finally block. The cycle-hook integration is tested only against fixed source to avoid an unbounded database request; bounded unit reproductions establish the original defect.

## Compatibility and limits

- Existing getParents positional arguments and ancestor order remain compatible. Cycle detection now intentionally rejects corrupt ancestry with 400. There is no arbitrary depth cap.
- The parent filter reads only descendant IDs with trusted internal access so hidden nodes cannot break cycle prevention. It forwards the request/transaction, supports custom parent names and terminates on corrupt cyclic links. The final relationship query retains normal read access. Large subtrees require one query per generation and an exclusion-ID list; live PostgreSQL/MongoDB and large-tree performance remain remote/manual checks.
- Internal document IDs retain the existing relative-ID href behavior. Application route resolution, discussed upstream separately, is not supplied by this patch. It prevents numeric IDs from suppressing all email delivery.
- The table wrapper fix covers generated tables in paragraphs, including surrounding text. Arbitrary formatting or links wrapped around a table and email-client-specific layout are not certified.
- Ethereal account reuse is per process, across module reloads; separate workers/processes keep separate accounts. Each adapter still constructs its own transport and preserves sender/recipient settings. No real email, test account or payment was sent/created during validation.
- SEO recognition uses the existing component marker logic. Authentication, Admin access and global document read access still run. Automatic fields are injected only for explicitly configured globals, as before. This is a scoped server authorization fix, not a claim to fix every client error-handling symptom in #18311.
- No dependency, lockfile, workflow, threshold or default access-control change is included. The new unit and integration specs are discovered by the existing full PR CI.
