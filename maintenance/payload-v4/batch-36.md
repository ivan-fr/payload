## Scope and exclusions

Context isolation is shallow: explicitly passing a new top-level context does not deep-clone objects stored inside it. Transaction updates remain shared through the scoped request proxy. Calls without an explicit context override continue to share inherited request context. A distinct population loader is intentional when context changes because read hooks can depend on that context.

The multipart change exposes the existing helper under its current v4 name. It does not add automatic multi-document creation, change built-in endpoint body shapes, or add the old private v3 function name as an alias. Custom endpoint code still owns access checks and temporary-file cleanup. Tests use separately named file parts.

Reports about async slugification, async tenant validation, several disabled storage adapters and authentication locale forwarding were inspected and excluded because the relevant code was already corrected or replaced on this base. The `admin.preview` report #14550 was also excluded: the current global-specific type already supports it. No correction to its valid documentation is counted.
